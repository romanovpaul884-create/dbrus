# Как внедрить schema.org на dbrus.ru

Пошаговая инструкция «с нуля». Ничего знать про MODX заранее не нужно —
делайте по пунктам. После каждого этапа есть **«Как проверить»**.

> Все имена кнопок и пунктов меню — как в админке MODX Revolution 3.

---

## Что вообще происходит

`schema.org` — это разметка для Google и Яндекса в виде маленького
JSON-блока в `<head>`. Она нужна, чтобы поисковики понимали, что у вас
на странице (компания, статья, проект дома с ценой, хлебные крошки).
В выдаче появляются «звёзды», цены, хлебные крошки, картинки.

Я уже подготовил **6 чанков** (это «вставки» в MODX) в репозитории:

```
core/elements/chunks/seo/
    schema.tpl                ← главный «диспетчер», его подключаем в шаблон
    schema_organization.tpl   ← инфа о компании (общая)
    schema_website.tpl        ← инфа о сайте (общая)
    schema_breadcrumb.tpl     ← хлебные крошки (общие)
    schema_article.tpl        ← для страниц статей
    schema_house.tpl          ← для страниц проектов домов
```

**Ваша задача:** перенести их в админку, прописать пару настроек, привязать
к нужным шаблонам и убедиться, что Google «видит» разметку.

---

## ВАЖНО до старта

1. Сделайте бэкап БД. В админке: **Управление → Резервные копии** или
   через хостинг.
2. Узнайте у разработчика/хостинга, установлен ли **pdoTools**. Без него
   Fenom-синтаксис (`{var}`, `{if}`, `{$_modx->...}`) работать не будет.
   Проверка: **Дополнения → Установщик → Установленные**, должен быть
   `pdoTools`. Если нет — установите бесплатно из репозитория MODX.
3. Если есть `Login`-extra — обновите до **≥ 1.9.14** (CVE-2024-55039).

## Шаг 1. Создать системные настройки

Это «глобальные переменные» — телефон, email, ссылки на соцсети. Чанк
`schema_organization` будет читать их оттуда.

**Куда идти:** `Админка → Система (шестерёнка вверху) → Системные настройки`.

Нажимаете **«Создать новую настройку»** и заводите по очереди.

> Поле **«Пространство имён»** для всех ставьте `core` или `dbrus` —
> неважно, главное единообразно. **«Имя»** — то же что ключ. **Тип** —
> везде «Текстовое поле», за исключением широкого `dbrus_address`
> (можно «Текстовая область»).

### 1.1. Контакты и адрес

| Ключ                | Значение (пример)                               |
| ------------------- | ----------------------------------------------- |
| `dbrus_phone`       | `+74957557617`                                  |
| `dbrus_email`       | `info@d-brus.ru`                                |
| `dbrus_region`      | `Москва`  (для регионов: `Московская область`)  |
| `dbrus_city`        | `Москва`                                        |
| `dbrus_address`     | `м. Домодедовская, …`                           |
| `dbrus_postal_code` | `115582`                                        |
| `dbrus_geo_lat`     | `55.610542`  (широта офиса)                     |
| `dbrus_geo_lng`     | `37.717834`  (долгота офиса)                    |
| `dbrus_open_hours`  | `Mo-Su 09:00-21:00`  (формат schema.org)        |

> Координаты можно взять в Яндекс.Картах: правый клик на точке → «Что
> здесь?» → копировать «широту, долготу». Часы работы пишите в
> [формате schema.org](https://schema.org/openingHours): двухбуквенные
> дни недели через дефис, время в `HH:MM`.

### 1.2. Соцсети (sameAs)

| Ключ               | Значение (пример)                |
| ------------------ | -------------------------------- |
| `dbrus_vk`         | `https://vk.com/dbrus`           |
| `dbrus_telegram`   | `https://t.me/dbrus`             |
| `dbrus_youtube`    | `https://youtube.com/@dbrus`     |
| `dbrus_whatsapp`   | `https://wa.me/74957557617`      |
| `dbrus_instagram`  | (если есть)                      |
| `dbrus_dzen`       | `https://dzen.ru/dbrus`          |
| `dbrus_ok`         | `https://ok.ru/dbrus`            |
| `dbrus_rutube`     | `https://rutube.ru/channel/...`  |

> Незаполненные оставляйте пустыми — они автоматически выпадут из
> JSON-LD, ошибки не будет.

### 1.3. Карточки в каталогах и бизнес-профили (sameAs)

Это критично важно для SEO: ссылки на ваши профили в Я.Бизнесе/2ГИС
помогают поисковикам подтвердить, что сайт принадлежит реальной
компании, и склеить рейтинги/отзывы из этих каталогов с сайтом.

| Ключ                     | Что вставить                                              |
| ------------------------ | --------------------------------------------------------- |
| `dbrus_yandex_business`  | URL карточки в **Яндекс.Бизнесе** / Я.Картах              |
| `dbrus_yandex_maps`      | URL точки в **Я.Картах** (если карта отдельным линком)    |
| `dbrus_2gis`             | URL карточки в **2ГИС**                                   |
| `dbrus_google_business`  | URL/share-ссылка на **Google Business Profile**           |
| `dbrus_yandex_market`    | URL магазина на **Яндекс.Маркете** (опц.)                 |
| `dbrus_avito`            | URL профиля на **Авито** (опц.)                           |
| `dbrus_zoon`             | URL карточки на **Zoon** (опц.)                           |
| `dbrus_yandex_uslugi`    | URL анкеты в **Яндекс.Услугах** (опц.)                    |

> **Где взять ссылку на Я.Бизнес:** залогиньтесь на
> https://yandex.ru/sprav/ , зайдите в свою карточку → «Поделиться» →
> копировать ссылку. Должно начинаться с `https://yandex.ru/maps/org/...`
> — это и есть канонический URL.

> **2ГИС:** на 2gis.ru найдите карточку, нажмите «Поделиться» →
> «Скопировать ссылку». URL вида `https://2gis.ru/moscow/firm/...`.

> **Google Business:** в Google Maps найдите место → «Поделиться» →
> «Копировать ссылку». URL `https://maps.app.goo.gl/...` или
> `https://www.google.com/maps/place/...`.

### 1.4. Технические настройки

| Ключ                          | Значение (пример)                              |
| ----------------------------- | ---------------------------------------------- |
| `dbrus_logo`                  | `assets/templates/dbrus/images/logo.svg`       |
| `dbrus_search_url_template`   | `search?q={search_term_string}`                |
| `dbrus_schema_template_map`   | (заполним на шаге 4, пока пусто)               |

**Как проверить:** в списке настроек ищите по слову `dbrus` — должно
быть **до 30 строк** (4 технических + 9 контактных + 8 соцсетей + 8
каталогов). Минимально обязательно заполнить `dbrus_phone`, `dbrus_email`,
`dbrus_city`, `dbrus_address` и хотя бы одну ссылку на Я.Бизнес/2ГИС.

## Шаг 2. Перенести чанки из git в админку

В MODX чанки живут в БД, а не в файлах. Есть 2 способа их подключить:

У заказчика templating через **Fenom + файловые шаблоны** (`{include 'file:new_design/...'}`),
и `templates_dir` настроен на `core/elements/`. Поэтому SEO-чанки лежат
просто **файлами** рядом с дизайном. Создавать что-либо в админке (раздел
«Чанки») **не нужно** — никаких ручных копипастов.

**Что делать:**

1. Залейте папку `core/elements/new_design/seo/` из git на сервер
   (через FTP/SSH/файловый менеджер хостинга), сохраняя структуру:
   ```
   core/elements/new_design/seo/
       schema.tpl
       schema_organization.tpl
       schema_website.tpl
       schema_breadcrumb.tpl
       schema_article.tpl
       schema_house.tpl
   ```
2. Всё. Никаких других действий — Fenom видит файлы автоматически
   через `{include 'file:new_design/seo/schema.tpl'}`.

**Как проверить, что путь корректный:** в `core/elements/new_design/`
рядом должны быть уже существующие папки `main/`, `pages/`, `sections/`,
`tpls/`, `mfilter/`, `components/`. Папка `seo/` встаёт туда же.

> **Важно про права:** убедитесь, что у `seo/` и файлов внутри такие же
> права, как у соседних `.tpl`-файлов в `main/`/`pages/` (обычно `0644`
> на файлы, `0755` на папку). Иначе Fenom не сможет их прочитать.

## Шаг 3. Создать TV (Template Variables)

TV — это дополнительные поля у страницы (картинка статьи, цена дома).
Без них чанки `schema_article` и `schema_house` не получат данные.

**Куда идти:** **Элементы → правый клик по «Параметры шаблона (TV)» → Создать**.

### TV для статей

| Имя TV                  | Тип ввода | Описание                            |
| ----------------------- | --------- | ----------------------------------- |
| `article_image`         | Image     | Главное изображение статьи          |
| `article_image_width`   | Число     | Ширина картинки, px (опц.)          |
| `article_image_height`  | Число     | Высота картинки, px (опц.)          |
| `article_author`        | Текст     | Автор статьи (опц.)                 |
| `article_summary`       | Textarea  | Краткое описание (опц.)             |
| `article_section`       | Текст     | Рубрика (опц.)                      |

### TV для проектов домов

У вас **уже заведены и заполняются** через mFilter2/pdoPage (см.
`core/elements/new_design/pages/index.tpl`):

| Имя TV             | Что значит                                | Идёт в schema как        |
| ------------------ | ----------------------------------------- | ------------------------ |
| `house_namem`      | Название проекта (бренд)                  | `name`                   |
| `house_name`       | Внутреннее имя/код                        | `sku` (если нет `house_sku`) |
| `house_cost`       | Цена в рублях (число)                     | `offers.price`           |
| `house_size`       | Габариты `10x12`                          | `additionalProperty`     |
| `house_square`     | Общая площадь, м²                         | `additionalProperty`     |
| `house_floors_upd` | Этажность                                 | `additionalProperty`     |
| `house_style`      | Стиль                                     | `additionalProperty`     |
| `built_house_type` | Тип постройки                             | `additionalProperty`     |
| `house_popular`    | Флаг "популярный" (для фильтра, в schema не идёт) | — |

> **Важно по `house_cost`:** в TV должно лежать **голое число без пробелов
> и без « р.»** (например `2949375`). Если у вас сейчас формат
> `2 949 375 р.` — Schema-блок будет невалидным. Либо чините TV, либо
> попросите доработать вывод цены отдельно (форматировать только при
> отображении).

**Опционально** — заведите эти TV, если хотите более богатую разметку
(пустые/несуществующие просто отбрасываются):

| Имя TV               | Тип ввода | Что даёт                                   |
| -------------------- | --------- | ------------------------------------------ |
| `house_sku`          | Текст     | Артикул проекта (если ведёте отдельно)     |
| `house_image_main`   | Image     | Главное фото (если не использовать ms2gallery) |
| `house_currency`     | Текст     | Валюта, по умолчанию `RUB`                 |
| `house_availability` | Список    | `InStock` / `PreOrder` / `OutOfStock`      |
| `house_material`     | Текст     | Материал (брус / каркас / газобетон …)     |
| `house_area_living`  | Число     | Жилая площадь, м²                          |
| `house_bedrooms`     | Число     | Количество спален                          |
| `house_bathrooms`    | Число     | Количество санузлов                        |
| `house_rating_value` | Число     | Средняя оценка (1–5)                       |
| `house_rating_count` | Число     | Количество отзывов                         |

> **Картинки**: если `house_image_main` не задан, чанк сам подтянет
> первый файл из ms2gallery (`msResourceFile`) — у вас на каталоге
> ms2gallery и так используется, дубль вводить не надо.

### TV-«переключатель» типа разметки (опционально)

| Имя TV                  | Тип ввода | Описание                            |
| ----------------------- | --------- | ----------------------------------- |
| `resource_schema_type`  | Список    | Значения: `article`, `house`, `none` |

> **Как настроить «Список»:** при создании TV → вкладка **«Параметры
> ввода»** → в поле **«Возможные значения»** напишите:
> `==||article==article||house==house||none==none`
> (`==` = «без значения», что-бы можно было не выбирать).

**Привязка TV к шаблонам:** в каждом TV откройте вкладку **«Шаблоны»**
и поставьте галки на тех шаблонах, где TV должен показываться.
- Все `article_*` → шаблон страницы статьи.
- Все `house_*` → шаблон карточки проекта дома.
- `resource_schema_type` → можно везде.

**Как проверить:** откройте любую страницу статьи в дереве ресурсов
слева → внизу должна появиться вкладка **«Параметры шаблона»** с полями
`article_image`, `article_author` и т.д.

## Шаг 4. Подключить `seo/schema.tpl` в `meta.tpl`

`<head>` у вас в файле **`core/elements/new_design/main/meta.tpl`**.
Открыть его (через FTP/файловый менеджер хостинга) и **прямо перед
`</head>`** добавить одну строку.

### Что было

```fenom
	<div class="chunck-metrika">[[$metrika]]</div>
</head>
```

### Что станет

```fenom
	<div class="chunck-metrika">[[$metrika]]</div>
	{include 'file:new_design/seo/schema.tpl'}
</head>
```

Всё. Один include — он сам подтянет Organization, WebSite, BreadcrumbList,
а на нужных страницах ещё Article или Product.

> Никакого `{ignore}` оборачивать не нужно — внутри schema-чанков нет
> литеральных `{` и `}`, всё валидно для Fenom.

### Какой страницей какой блок выводится

Управляется двумя независимыми механизмами (любой из них):

**А) Системная настройка `dbrus_schema_template_map`** —
карта `id_шаблона:тип` через запятую. Например, если у вас:
- шаблон страницы статьи имеет ID `5`,
- шаблон карточки проекта — `7` (и/или `8`),

— то в этой настройке пишите:

```
5:article, 7:house, 8:house
```

ID шаблона видно в админке: **Элементы → Шаблоны** — колонка id рядом
с именем. Заполните только те, которыми действительно пользуетесь.

**Б) TV `resource_schema_type`** на конкретной странице — ручной override.
Значения `article`, `house`, `none` (`none` — отключить контекстный блок
на этой странице). Если у конкретного ресурса этот TV выставлен — он
имеет приоритет над `dbrus_schema_template_map`.

> Если оба механизма пустые — на любой странице выведутся только три
> общесайтовых блока (Organization + WebSite + Breadcrumb). Это уже
> валидная микроразметка, ошибок не будет.

**Как проверить (промежуточно):**
1. Откройте главную сайта в браузере.
2. Ctrl+U → **«Просмотр кода страницы»**.
3. Ctrl+F по слову `application/ld+json` — должно найтись 2 блока
   (`Organization`, `WebSite`); на любой внутренней странице — ещё
   `BreadcrumbList`.
4. Если блоков нет:
   - проверьте, что строку `{include 'file:new_design/seo/schema.tpl'}`
     вы вставили именно в `meta.tpl`, а файл `core/elements/new_design/seo/schema.tpl`
     реально лежит на сервере;
   - очистите кэш: **Управление → Очистить кэш**.
   - в редких случаях помогает в свойствах ресурса снять галку «Кэшируемый»
     и посмотреть исходник один раз без кэша.

## Шаг 5. Очистка кэша

После каждого изменения чанков/шаблонов/настроек:

**Управление (вверху) → Очистить кэш → Site Cache + Resource Cache + Menu Cache**.

Или CTRL+SHIFT+F5 в браузере для жёсткой перезагрузки.

## Шаг 6. Финальная проверка

### 6.1. Google Rich Results Test (главная проверка!)

1. Откройте https://search.google.com/test/rich-results
2. Введите URL страницы (главную, статью, проект дома — по очереди).
3. Нажмите **«Test URL»**.
4. Должны увидеть зелёные плашки:
   - **Главная**: `Organization`, `WebSite`.
   - **Любая внутренняя**: ещё `Breadcrumbs`.
   - **Статья**: + `Article`.
   - **Проект дома**: + `Product` (с ценой и доступностью).
5. **Жёлтые** предупреждения (например, «recommended field image») —
   это намёк дополнить TV; **красные** ошибки — нужно чинить.

### 6.2. Schema.org validator

https://validator.schema.org/ — то же, что Google, но строже.
Полезно проверить на отсутствие синтаксических ошибок в JSON.

### 6.3. Яндекс.Вебмастер

В **Вебмастере → Инструменты → Валидатор микроразметки** добавьте те же
URL. Яндекс понимает schema.org, но иногда подсвечивает свои нюансы.

### 6.4. View source: дубли

В исходнике карточки проекта должно быть **ровно 4 блока** JSON-LD
(Organization, WebSite, BreadcrumbList, Product). Если их 8 — значит
`{include 'file:new_design/seo/schema.tpl'}` стоит дважды (в `meta.tpl`
и где-то ещё). Уберите один.

## Шаг 7. Что осталось со старого HTML

В выгруженном `upload/stati-html.txt` (листинг статей) уже есть
**микроразметка `BreadcrumbList`** через атрибуты `itemscope` /
`itemtype` — она не мешает нашему JSON-LD, поисковики поймут оба
варианта. Можно оставить как есть, можно постепенно удалить (когда
убедитесь, что наш JSON-LD работает).

JSON-LD на загруженных страницах **не было** — поэтому всё, что мы
делаем, добавит сайту микроразметку с нуля.

## Если что-то не работает — алгоритм

1. **JSON в коде есть, но Rich Results Test показывает ошибку.**
   Скопируйте содержимое `<script type="application/ld+json">` и
   вставьте в https://jsonlint.com/ — чаще всего проблема в неэкранированной
   кавычке внутри названия (`"Дом "БРУС""`). Проверьте поле в админке.

2. **JSON-LD не появляется в коде вообще.**
   - Кэш: очистите.
   - Файл: точно ли строка `{include 'file:new_design/seo/schema.tpl'}`
     стоит в `meta.tpl` (не в `header.tpl`!) перед `</head>`.
   - Файлы загружены: проверьте, что папка `core/elements/new_design/seo/`
     реально появилась на сервере и в ней лежат все 6 `.tpl`-файлов.
   - Права: `chmod 0644` на файлы, `0755` на папку.

3. **Ошибка вида `Cannot read property of null` или пустой `Product`.**
   Часто значит, что у текущего ресурса пуст `house_cost` или другие TV.
   Это нормально — наш чанк просто пропустит блок offers. Проверьте
   страницу, у которой TV точно заполнены.

4. **Цена в `schema_house` не та, что на сайте.**
   В TV `house_cost` должно лежать **голое число без пробелов и без « р.»** —
   только цифры (`2949375`). Все красивые форматы (с пробелами, валютой) —
   только в выводе на сайте, в schema идёт сырое число.

5. **На главной не нужен Breadcrumb, а он выводится.**
   Чанк `schema_breadcrumb` сам пропускает рендер на главной (id ==
   `site_start`). Если всё равно выводится — проверьте в **Системные
